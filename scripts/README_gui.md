# GUI 控制台

入口：`scripts/gui_control.sh`。Qt 桌面窗口，分为关节、末端位姿、参数三个页面，实时显示目标、命令和反馈，
右侧是从 SDK 自带 URDF 和 STL 网格加载的三维模型。默认连接模拟驱动，不打开串口。

默认使用 `--profile tuned` 控制参数，见[主 README](../README.md#默认控制参数)。
重力补偿的参数和调试方法见 [README_gravity.md](README_gravity.md)，界面会显示补偿比例和七轴前馈力矩。

## 运行

```bash
# 模拟模式：自动连接理想位置驱动
./scripts/gui_control.sh

# 真机模式：打开窗口后点击“连接真机”，才打开串口并在当前位置使能保持
./scripts/gui_control.sh --execute --port /dev/ttyUSB3
```

连接真机时不会自动回零或移到准备姿态。连接后，命令和滑块都从当前关节反馈初始化，不沿用上一次的目标。
连接前请关闭键盘工具和其他占用同一串口的程序。

## 界面

1. **关节**：用 J1–J7 的滑块或数字框设置目标角度（度），范围取自 URDF。滑块下方显示平滑后的命令角度和实际反馈角度。
   数字框中输入数值后按 Enter 生效，也可以用上下箭头微调。
2. **末端位姿**：X/Y/Z 设置 TCP 在 `base_link` 中的绝对位置（mm），Roll/Pitch/Yaw 设置绝对朝向（°）。
   欧拉角为固定轴 XYZ，旋转矩阵 `Rz(Yaw) Ry(Pitch) Rx(Roll)`，与 URDF 的 RPY 和 SciPy
   `Rotation.from_euler("xyz", ...)` 一致。改位置时保持当前选定的朝向，改朝向时保持选定的位置。
   目标经 IK 求解和校验后，按关节空间平滑轨迹执行。
   命令和反馈的欧拉角按标准范围显示，在 ±180° 附近可能跳变；IK 使用旋转矩阵，不会因此多转一圈。
   Pitch 接近 ±90° 时欧拉角奇异，建议小幅调整。
3. **参数**：修改速度、加速度、jerk、增益和保护阈值，点击“应用参数”后生效。
   右列是控制进程确认的当前值。“恢复推荐值”只填入当前配置的推荐值，仍需点击应用。
4. **URDF 视图**：可以切换显示“实际反馈”“平滑命令”“目标预览”。左键拖动旋转，滚轮缩放，“复位视角”恢复初始视角。
   红、绿、蓝轴分别为基坐标 X、Y、Z，橙色球是 TCP 原点（在模型内部时可能被遮挡），TCP 处的短三色轴随末端朝向旋转。

滑块是位置目标：松开滑块后，机械臂继续平滑地移动到目标。这一点与键盘工具的松键即停不同。
点击“保持”、按空格或窗口失去焦点时，取消剩余运动，保持在已发送的命令位置。
切换关节/末端位姿页面或进入参数页时，旧目标会被取消，收到保持确认后再同步滑块。

| 按钮 / 快捷键 | 行为 |
| --- | --- |
| P · 准备姿态 / P | 平滑移到准备姿态（默认为零位末端 −Y 5 cm、+Z 5 cm，朝向不变） |
| H · 回零 / H | 平滑回到标定零位 |
| 保持 / Space | 冻结当前命令位置并保持，取消尚未完成的 IK 和后续目标 |
| 恢复 · Recover | 阻尼保持状态下，在当前实测位置恢复位置保持 |
| 停止 / Esc | 释放力矩，之后不再接受运动命令；需要断开后重新连接 |
| 断开 / 关闭窗口 / Ctrl-C | 停止、释放力矩并断开 |

按 P 或 H 后会切回关节页面。准备姿态、`--tcp` 和 `--ready-q` 与[键盘工具](README_keyboard.md#准备姿态)相同。
零位附近 J2、J4 在限位上，建议先按 P 进入准备姿态再调整末端位置。

## 显示的数值

- **目标**：用户设置的位置，或由 IK 解出的关节角。末端位姿求解尚未完成时，模型显示“上一有效目标预览”。
- **命令**：100 Hz 平滑轨迹当前发给控制进程的位置。
- **实际反馈**：SDK 收到的编码器关节角。反馈 TCP 由这些角度经 FK 算出，不是外部测量值。
  停止后标为“最后收到的反馈”，断开后清空。
- 模拟模式按理想跟踪计算反馈，不模拟重力、惯性和碰撞。URDF 视图只显示姿态，不做物理仿真。

## 末端位姿求解

IK 和 URDF 渲染各在一个独立进程中运行，控制进程仍以 100 Hz 独立运行。反馈约 20 Hz 刷新，三维视图最高约 12.5 Hz。

- 同一时间只有一个 IK 请求在计算，并只保留最新的目标；过时的结果不会触发运动。
  求解期间上一个有效轨迹继续执行；求解失败或校验不通过时保持当前位置。
- 求解始终固定目标朝向，不会为了求出位置而放宽朝向。
  搜索范围依次为当前命令附近 ±0.6 rad、±1.4 rad 和完整关节范围，都与 URDF 限位取交集。
  小幅目标通常在第一级就找到解，较远的目标才使用多初值搜索。
- 最终用独立的 FK 校验：位置误差 ≤ 0.1 mm，方向误差 ≤ 0.001 rad。
- 每个请求总共 3 s 求解时间，GUI 另留 0.5 s 余量；3.5 s 内没有结果就保持当前位置并重启 IK 进程。
  目标停止变化 80 ms 后，已运行超过 150 ms 的旧求解会被取消。
- 状态栏显示找到解的搜索级别和耗时。找不到解不代表目标一定不可达，数值搜索不保证找到所有可达位姿。
- 目标位姿的朝向是固定的，但关节空间轨迹的中间过程不保证保持该朝向。

## 参数

保持和规划都基于命令参考，不会用反馈角覆盖参考，避免承重静差被反复清掉（原因见[键盘工具](README_keyboard.md#保持与承重)）。

| 参数 | `tuned` 推荐值 | `legacy` 推荐值 | 范围 | 启动参数 |
| --- | --- | --- | --- | --- |
| 关节最大速度 | 0.15 rad/s | 0.15 rad/s | 0.01–1 rad/s | `--joint-speed` |
| 关节最大加速度 | 0.5 rad/s² | 0.5 rad/s² | 0.1–5 rad/s² | `--joint-accel` |
| 关节最大 jerk | 2 rad/s³ | 2 rad/s³ | 0.5–50 rad/s³ | `--joint-jerk` |
| Kp | 100（J2、J4 为 200） | 60 | 0.01–100 | `--kp` |
| Kd | 1（J2、J4 为 1.41） | 0.5 | 0.01–5 | `--kd` |
| 命令领先暂停阈值 | 0.08 rad | 0.08 rad | 0.01–0.3 rad | `--lead-limit` |
| 跟踪误差阈值 | 0.1 rad | 0.2 rad | 0.02–0.5 rad | `--tracking-limit` |
| 单目标运动超时 | 60 s | 60 s | 5–300 s | `--move-timeout` |

- 范围是程序允许的设置范围，不是机械臂在任意负载下的安全范围。速度指关节角速度，不是 TCP 线速度。
- 暂停阈值必须小于跟踪误差阈值。界面和控制进程都会校验，有一项不合法时整组拒绝。
- 应用参数时 Kp、Kd 没有改动，则保留 J2、J4 的单独增益；改了 Kp 或 Kd，所有关节改用统一增益。
- 应用参数时，先取消旧目标和进行中的 IK，在当前命令位置保持，再一次性更新全部参数。
  确认之前禁用运动输入，确认超时则停止。
- 参数在本次窗口内断开重连后仍然保留，关闭窗口后不保存；下次启动使用推荐值或命令行参数。
- 命令领先反馈超过暂停阈值时暂停推进轨迹；跟踪误差超过阈值、心跳丢失等故障的处理与键盘工具相同，
  见[保护与停止](README_keyboard.md#保护与停止)。运动超时后停在当前参考位置保持。

```bash
./scripts/gui_control.sh --execute --joint-speed 0.15 --joint-accel 0.5 --joint-jerk 2
# 设置实际工具的 TCP，单位 m、rad
./scripts/gui_control.sh --tcp 0 0 0.08 0 0 0
```

GUI 发出的完整关节目标使用 `MOVE` 命令，运动超时作用于 MOVE、HOME、READY。键盘工具的小步 `TARGET`
仍受 0.12 rad 和 5 s 的限制。参数通过 `CONFIG 序号 speed accel jerk kp kd lead tracking timeout` 下发，
状态中的 `config_ack` 是已处理的请求序号，`config_revision` 是已成功应用的序号，`config_error` 是拒绝原因。
停止后不能重新配置或使能。

程序不做自碰撞、工具或环境碰撞检查；关节空间轨迹不保证 TCP 走直线。软件停止不是硬件急停。

## 安装与测试

需要 Ubuntu 和 Python 3.12，并在完整的仓库中运行（需要 URDF 和 STL 文件）：

```bash
./scripts/setup_gui.sh
./scripts/gui_control.sh
```

`setup_gui.sh` 按 `R1_IK_PYTHON` → 仓库内 `.venv-ik` 的顺序选择 Python，都不存在时创建 `.venv-ik`，
然后安装 [requirements-gui.txt](requirements-gui.txt) 并构建控制进程。如果系统缺少 Qt 需要的 `libxcb-cursor0`，
它从系统的 apt 源下载该包并解压到 `build/gui-runtime/`，不需要 sudo，也不修改系统；启动脚本会自动加载这份运行库。
安装需要联网，运行时不需要。

源码：`gui_control.py`（界面）、`gui_control_core.py`（控制逻辑和异步 IK）、`gui_urdf.py`（URDF 渲染）、
`gui_settings.py`（参数定义）。界面使用 [Qt for Python](https://doc.qt.io/qtforpython-6/)，
模型用 [PyBullet](https://github.com/bulletphysics/bullet3) 离屏渲染。

```bash
.venv-ik/bin/python -m pytest -q tests/test_gui_control.py tests/test_keyboard_control.py tests/test_arm_control.py
ctest --test-dir build/keyboard --output-on-failure
```

日志默认写到 `build/keyboard/logs/gui-<时间戳>.jsonl`，可以用 `--log /path/to/gui.jsonl` 指定。
