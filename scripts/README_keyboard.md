# R1-7A 键盘末端点动

入口：`scripts/keyboard_control.sh`。弹出本机键盘控制窗口，支持真实按下/松开事件。
默认只连接模拟驱动，不打开串口；加 `--execute` 才连接机械臂。

DEX1-1 的可选重力补偿见 [README_gravity.md](README_gravity.md)。
与 GUI 共用 `--gravity-profile`、`--gravity-scale`、`--carrying` 参数；调优配置下默认开启 100%，见下文。

## 调优配置（2026-11-07 起默认）

键盘控制和 GUI 默认使用 `--profile tuned`，即 2026-11-03 在 R1-7A + DEX1-1 实机上验证过的参数（见 `tuned_profile.py`）：

| 项目 | tuned（默认） | legacy（`--profile legacy`，原默认） |
|---|---|---|
| 增益 | J2、J4：Kp 200 / Kd 1.41；其余关节 100 / 1 | 全部关节 Kp 60 / Kd 0.5 |
| 重力补偿 | 100%，使用 `config/dex1_gravity.json` | 关闭 |
| 关节积分外环 | ki 1.5/s，每关节力矩权限 3 N·m | 无 |
| 跟踪误差停止阈值 | 0.1 rad（Kp 200 时约 20 N·m） | 0.2 rad |
| 软故障（心跳丢失、跟踪超限、非法目标等） | **阻尼保持，不释放力矩**；可恢复 | 释放力矩 |
| 连接时有关节略微越限 | 不超过 0.2 rad 时自动移回（例如释放力矩后 J6 落到限位外） | 拒绝使能 |

- **防振荡**：积分在关节越过参考后保持不变，不会在静摩擦带内来回跳。参考刚停下的 0.5 s 内不作这一判断。
- **实测（2026-11-03）**：10 mm 单步误差 0.26–0.66 mm，静置 0.62 mm，阻尼漂移 0.02 mm。
- **覆盖参数**：命令行显式给出的参数优先于配置。显式给出不同的 `--kp`/`--kd` 时，改为全部关节统一增益，积分仍为 3 N·m。
- **恢复**：阻尼保持时，键盘窗口按 **Enter**，GUI 点 **恢复 · Recover**，即在当前实测位置恢复位置保持。Esc 或“停止”仍会释放力矩。
- **GUI 参数页**：“应用参数”时，如果 Kp/Kd 没有改动，保留逐关节增益；改了 Kp/Kd 则改为统一增益。“恢复推荐值”填入的是当前配置的推荐值。

## 本机运行

当前机器已装好依赖并编译驱动，可直接使用：

```bash
cd r1-7a_sdk   # 仓库根目录

# 先在模拟模式熟悉按键
./scripts/keyboard_control.sh

# 真机：启动后读取当前反馈，并以调优配置使能位置保持（--profile legacy 为原来的 kp=60 / kd=0.5）
./scripts/keyboard_control.sh --execute --port /dev/ttyUSB3

# 更小步长，例如每次 1 mm
./scripts/keyboard_control.sh --execute --step-mm 1
```

点击控制窗口使其获得键盘焦点。窗口分别显示实际反馈 TCP、命令参考 TCP、关节跟踪误差和七轴反馈。
这是桌面窗口程序，需要图形会话；普通 SSH 文本终端不能可靠地提供松键事件。

### 两点之间的平滑与连续点动

方向点动、P 准备姿态、H 回零都使用 100 Hz 的七轴同步轨迹，限制关节速度、加速度及
加加速度（jerk），平滑起步和到位。运动中更新目标时继承当前参考速度与加速度。
持续按键会提前求解下一小步，取消了原先到点后固定等待 150 ms 的逻辑。
只保留一个预计算结果，在接近前一个目标时接入；发送的新目标距当前参考 TCP 不超过
`1.1 × 步长 + 0.2 mm`，避免积压远端目标和过度偏离指定轴线。

默认参数已生效，重新启动程序即可使用：

| 参数 | 默认值 | 可设置范围 |
| --- | --- | --- |
| `--joint-speed` | 0.15 rad/s | 0.01–0.3 |
| `--joint-accel` | 0.5 rad/s² | 0.1–2 |
| `--joint-jerk` | 2 rad/s³ | 0.5–20 |

需要更缓的起停，可降低加速度和 jerk，例如：

```bash
./scripts/keyboard_control.sh --execute --joint-accel 0.3 --joint-jerk 1
```

这些限制针对正常运动的命令轨迹。松键、空格、失焦和跟踪保护优先冻结当前命令位置，
不为完成平滑减速而继续向远端目标移动；Esc 仍停止并释放力矩。因此主动中断不保证
速度/加速度连续。预计算结果也会随松键作废，承重静差保持逻辑不变。

这是关节空间平滑，不保证 TCP 严格走直线或保持精确匀速。IK 较慢或跟踪保护介入时仍会减速/等待。
默认 P 点、2 mm 步长的六方向连续点动离线测试检查了不中途停点和参考 TCP 横向偏差
小于 0.5 mm；该数值仅是此模型、这些测试轨迹的结果，不是真机或整个工作空间的精度保证。

### “每按一次就下沉”修复

旧实现每次按下/松开方向键都把保持设定值改为实测角度，IK 也从实测角度重新起算。
PD 控制在重力下需要位置静差来提供承重力矩，反复清掉这段静差会导致逐次下沉。
当前实现改为：

- 松键、空格和失焦时冻结当时已经发送的关节设定值，取消后续目标，不用反馈角重置参考。
- IK 从连续的命令参考位置规划增量，保留承重静差；反馈仍用于限幅、故障和跟踪检查。
- 参考与反馈偏差超过 0.06 rad 时暂停生成新点动，保持已有参考。
- `HOLD` 表示参考轨迹已完成或被冻结，不表示实测误差为零。实际位置仍可能有静差及短暂收敛。

本次没有提高 kp/kd，也没有修改标定。新增了固定负载偏差模拟，覆盖 R/F、A/D
正反方向重复点按；旧逻辑下可复现逐次下沉，修复后参考保持连续。

每次启动自动写本地诊断日志到 `build/keyboard/logs/keyboard-时间戳.jsonl`，终端会打印完整路径。
日志包含按键、指令、关节反馈及参考值；可用 `--log /path/to/trace.jsonl` 指定位置（追加写入）。

### 先进入准备姿态

若从七轴零位开始，点击窗口后按 **P**，机械臂以限速方式移动到准备姿态并持续保持，
然后再使用方向键点动。启动程序本身仍只保持当前位置，不自动移动到准备姿态。

默认 P 点设为 **Home 末端位置沿基坐标 −Y 5 cm、+Z 5 cm**，X 不变，
保持 Home 的末端朝向。这里“前方”按现场确认使用 −Y。

默认零 TCP 时，Home 位置为 `(0.002674538, -0.034121936, 0.192920591) m`，
P 点位置为 `(0.002674538, -0.084121936, 0.242920591) m`。
采用以下离线求解并精化的关节角（J1..J7，rad）：

```text
0.006792101712  0.605442587728  0.003982975938  0.349301756762
-0.004018032920  0.256020348855  0.009633129608
```

约为 `[0.389°, 34.689°, 0.228°, 20.014°, -0.230°, 14.669°, 0.552°]`。
Home/P 朝向相同，因此配置固定 TCP 后，两点的上述相对位移仍成立；绝对坐标会变化。
J2/J4 离开零位下限，为双向 XYZ 点动留出活动余量。
在默认零 TCP 的离线测试中，六个方向各连续 10 次、每次 2 mm 的点动均通过求解。
这是 SDK 模型离线筛选的候选姿态，未确认现场安装、工具及周围障碍物是否允许到达。
默认平滑参数下，从零位理想运行约 4.6 秒；实际耗时取决于反馈跟踪。
空格或失焦可中途取消并保持；Esc 停止释放力矩。

可自定义准备姿态，单位 rad；P 使用它，H 始终仍回七轴零位：

```bash
./scripts/keyboard_control.sh --execute --ready-q \
  0.006792101712 0.605442587728 0.003982975938 0.349301756762 \
  -0.004018032920 0.256020348855 0.009633129608
```

准备姿态是工作位置，不是新的标定零位，不要修改 `joint_calib.txt`。
不同工具 TCP 可改变可达性，应按实际工具设置 `--tcp`。

| 按键 | 行为 |
| --- | --- |
| W / S | 末端沿 `base_link` 的 +X / −X 点动 |
| A / D | 末端沿 `base_link` 的 +Y / −Y 点动 |
| R / F | 末端沿 `base_link` 的 +Z / −Z 点动 |
| 松开方向键 | 取消剩余目标，冻结已发送的关节设定值并持续保持 |
| 空格 | 取消点动/回零，保持当前位置 |
| P | 移到配置的准备姿态，到位后继续保持 |
| H | 一键回已标定的七轴零位；到零后继续保持 |
| Esc | 停止，发送 mode 0 并释放力矩，锁定控制 |
| Q / 关闭窗口 / Ctrl-C | 停止、释放力矩并退出 |

切换到其他窗口或最小化也会取消运动并保持。重新获得焦点后须重新按方向键。
按 H / P 后自动完成回零 / 进入准备姿态，不必一直按住；空格、方向键或窗口失焦可以取消。
Esc 停止后不自动重新使能，要重新运行程序。**空格保持与 Esc 释放力矩是不同操作。**

## 点动方式

- 默认每次 Cartesian 增量为 **2 mm**，可通过 `--step-mm` 设置为 0.5–5 mm。
  持续按住会重复小步移动；同时按不同轴按键可以斜向移动，总步长不增加。
- 第一小步从当前命令参考的 FK 位置求解，后续从上一规划目标继续求解，避免静差被反复计入新目标；
  同一次持续按键期间保持开始时的参考末端方向。方向切换或重新按键后重新采集参考方向。
- 关节命令速度上限默认 **0.15 rad/s**，`--joint-speed` 可设置 0.01–0.3 rad/s。
  它是关节命令速度上限，不是精确的末端匀速控制；实际点动频率还取决于跟踪和 IK 耗时。
- `--tcp x y z roll pitch yaw` 设置从 `Link7` 到工具端点的变换（m/rad），默认为零。
  方向相对 SDK 的 `base_link`，不是相机、桌面或工具坐标；安装方式决定 +Z 是否朝上。
- 零位处 J2/J4 正好位于关节下限，某些方向可能没有满足限制的 IK 解。
  遇到不可达目标会取消该方向并保持，松开后可换另一个方向。

例如实际 TCP 沿 Link7 局部 Z 偏移 8 cm 时（请使用实际测量值）：

```bash
./scripts/keyboard_control.sh --execute --tcp 0 0 0.08 0 0 0
```

## 实现与停止语义

`keyboard_control.py`（Pygame 键盘窗口）→ 独立 IK 进程（复用 `arm_control.ArmIK`）→
`r1_keyboard_worker`（常驻 C++ SDK 控制，100 Hz）。
使用 [Pygame 按下/松开及窗口焦点事件](https://www.pygame.org/docs/ref/event.html)，
并核对当前按键状态。与单次 `goto` 不同，此程序正常松键后继续发送 FOC 位置保持，
不会结束命令后释放力矩。

平滑器采用 [Ruckig v0.15.3](https://github.com/pantor/ruckig/tree/v0.15.3) 的本地
state-to-state C++ 实现，优先使用相位同步，不可行时由库使用时间同步。源码、MIT 许可证
和版本/哈希记录随脚本保存在 `keyboard_native/third_party/ruckig/`，构建和运行不需要下载或云端服务。
每次计算还检查整条关节轨迹的位置极值，避免在线换目标时越过 URDF 限位。

松键/失焦时会作废尚未完成的 IK 结果，驱动将目标冻结为当时已发送的关节设定值；
不再继续远端目标的轨迹，也不重新捕获已经下沉的反馈角。反馈仅在最初使能时用来初始化设定值。
真实停止仍受事件处理、总线延迟和机械惯性影响，实际角度可能继续短暂收敛到负载下的平衡位置。
IK 在独立进程运行，耗时求解不会阻塞键盘窗口及其心跳。

驱动使用现有 `config/joint_calib.txt` 和 SDK `ArmMotorBus`，不写零偏、不清故障，
不自动回零。启动时通过零力矩 FOC 请求反馈，再以当前反馈使能位置保持；
这段反馈获取并非被动只读，需有机械支撑。已知微小编码器偏差允许关节反馈在 URDF
边界外 0.03 rad 内；发送目标仍严格限制在 URDF 范围。

驱动检查关节范围、反馈新鲜度（200 ms）、电机故障、FOC 状态及跟踪误差；
每次点动目标相对反馈不超过 0.12 rad；若新的命令增量会把命令/反馈偏差继续扩大到超过
0.08 rad，则暂停参考轨迹，等待反馈跟上；恢复时从冻结位置以零参考速度/加速度重新起步。
不会让固定参考跟随下沉反馈继续漂移。
跟踪偏差超过 0.2 rad 仍会故障停止。
GUI 心跳超过 500 ms、进程退出、串口反馈异常等会停止并释放力矩。
H 回零使用相同关节速度/加速度/jerk/领先限制，60 秒未完成则停止；单个点动目标 5 秒未完成也会停止。
P 准备姿态使用相同限制和 60 秒超时。

保持依靠 PD 力矩，没有重力前馈，因此可能有静差；FK 显示值不代表工具实测精度。
没有自碰撞/环境碰撞规划，回零是关节空间运动。此停止功能不是硬件急停。
保持期间也需要程序和供电正常；Esc/退出/故障会释放力矩，应支撑机械臂。
真机运行前关闭其他串口控制程序；驱动请求串口独占，但不能赶走已经打开串口的旧进程。

## 安装、编译与验证

启动器与 `arm_control.sh` 使用相同 Python 选择规则：`R1_IK_PYTHON` →
SDK 内 `.venv-ik` → 系统 Python。

```bash
# 其他机器：在你的 Python 3.12 环境安装
python -m pip install -r scripts/requirements-keyboard.txt

# 独立构建，不覆盖原 test_arm_lowlevel 或已修改的 libmotor_controller.so
./scripts/build_keyboard.sh

# 原生轨迹数值测试：速度、加速度、jerk、在线换点、限位和保持
ctest --test-dir build/keyboard --output-on-failure

# 本机离线回归：所有测试都使用模拟驱动，不连接机械臂
.venv-ik/bin/python -m pytest -q tests/test_keyboard_control.py tests/test_arm_control.py
```

构建输出在 `build/keyboard/r1_keyboard_worker`。核心实现位于
`scripts/keyboard_native/worker.cpp`；复用 SDK 的串口与协议源码，保留当前现场修复。
IK 的来源、单臂适配、许可证及坐标约定见 [README_ik.md](README_ik.md)。

验证范围：实际编译、理想及固定负载偏差模拟联调、异步 IK、按键松开/失焦/回零取消/停止锁定、
超时与无效指令拒绝、连续点动衔接、轨迹导数限幅，以及窗口离线渲染。
未连接或驱动真机，真机保持效果和运动方向需现场验证。
