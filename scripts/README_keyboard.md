# 键盘末端点动

入口：`scripts/keyboard_control.sh`。打开一个 Pygame 窗口，用键盘控制末端沿 `base_link` 的 X、Y、Z 方向点动，
松开按键后保持在当前命令位置。默认连接模拟驱动，加 `--execute` 才打开串口控制真机。

默认使用 `--profile tuned` 控制参数（增益、重力补偿、关节积分、阻尼保持），见[主 README](../README.md#默认控制参数)。
重力补偿的参数和调试方法见 [README_gravity.md](README_gravity.md)。

## 运行

```bash
# 模拟模式，先熟悉按键
./scripts/keyboard_control.sh

# 真机：读取当前反馈，在当前位置使能保持
./scripts/keyboard_control.sh --execute --port /dev/ttyUSB3

# 每步 1 mm
./scripts/keyboard_control.sh --execute --step-mm 1
```

需要图形桌面，点击窗口获得键盘焦点后才能操作。SSH 文本终端无法可靠地收到松键事件。
窗口显示反馈 TCP、命令 TCP、各关节跟踪误差和七轴反馈。

启动时不会自动移动到准备姿态或零位，只在当前位置保持。

## 按键

| 按键 | 行为 |
| --- | --- |
| W / S | 末端沿 `base_link` +X / −X 点动 |
| A / D | 末端沿 `base_link` +Y / −Y 点动 |
| R / F | 末端沿 `base_link` +Z / −Z 点动 |
| 松开方向键 | 取消剩余目标，保持在已发送的命令位置 |
| 空格 | 取消点动、回零或准备姿态运动，保持当前位置 |
| P | 移到准备姿态，到位后保持 |
| H | 回到标定零位（七轴全零），到位后保持 |
| Enter | 阻尼保持状态下，在当前实测位置恢复位置保持 |
| Esc | 停止：发送 mode 0 释放力矩，之后不再接受运动命令 |
| Q / 关闭窗口 / Ctrl-C | 停止、释放力矩并退出 |

窗口失去焦点或最小化时同样取消运动并保持，重新获得焦点后需要重新按方向键。
P 和 H 按一下即可，不需要按住；运动途中按空格、方向键或切走窗口都会取消。
Esc 之后要重新启动程序才能再次使能。空格只是保持，Esc 会释放力矩，两者不要混用。

## 点动方式

- 每次点动的笛卡尔步长默认 2 mm，`--step-mm` 可设为 0.5–5 mm。按住方向键会连续点动。
  同时按两个轴的键可以斜向移动，合成步长不变。
- 第一步从当前命令位置的 FK 开始求解，之后每一步从上一步的目标继续。一次按键期间保持按下时的末端朝向，
  换方向或重新按键时重新取朝向。
- 按住不放时，程序会在当前一步快结束时提前求解下一步，因此连续点动中间不会停顿。
  同一时间只保留一个预先求解的目标，且它离当前命令 TCP 不超过 `1.1 × 步长 + 0.2 mm`。
- `--tcp x y z roll pitch yaw` 设置 `Link7` 到工具端点的变换（m、rad），默认为零，即 `Link7` 原点。
  方向始终相对 `base_link`，与相机、桌面或工具坐标无关。
- 零位时 J2、J4 正好在关节下限，有些方向可能求不出满足限位的 IK 解。
  求不出解时取消该方向并保持，可以换一个方向，或先按 P 进入准备姿态。

例如工具端点在 `Link7` 局部 Z 方向 8 cm 处（请换成实测值）：

```bash
./scripts/keyboard_control.sh --execute --tcp 0 0 0.08 0 0 0
```

## 准备姿态

默认准备姿态的末端位置是零位末端位置沿 `base_link` −Y 平移 5 cm、+Z 平移 5 cm，朝向与零位相同。
默认 TCP 下，零位末端在 `(0.002674538, -0.034121936, 0.192920591) m`，准备姿态末端在
`(0.002674538, -0.084121936, 0.242920591) m`。对应关节角（J1..J7，rad）：

```text
0.006792101712  0.605442587728  0.003982975938  0.349301756762
-0.004018032920  0.256020348855  0.009633129608
```

约为 `[0.389°, 34.689°, 0.228°, 20.014°, -0.230°, 14.669°, 0.552°]`。这一姿态让 J2、J4 离开下限，
在模型中六个方向各连续点动 10 次（每次 2 mm）都能求解。它是离线用模型选出的，
现场安装、工具和周围障碍物是否允许到达需要自行确认。默认速度下从零位移过去约 4.6 s。

用 `--ready-q` 指定其他准备姿态（rad）。H 始终回七轴零位：

```bash
./scripts/keyboard_control.sh --execute --ready-q \
  0.006792101712 0.605442587728 0.003982975938 0.349301756762 \
  -0.004018032920 0.256020348855 0.009633129608
```

准备姿态只是工作起点，不要为此修改标定文件。

## 平滑轨迹

点动、P 和 H 都以 100 Hz 生成七轴同步轨迹，限制关节速度、加速度和加加速度（jerk），起步和到位都是平滑的。
运动中换目标时，新轨迹从当前的参考速度和加速度接续。

| 参数 | 默认值 | 范围 |
| --- | --- | --- |
| `--joint-speed` | 0.15 rad/s | 0.01–0.3 |
| `--joint-accel` | 0.5 rad/s² | 0.1–2 |
| `--joint-jerk` | 2 rad/s³ | 0.5–20 |

希望起停更缓时，可以同时降低加速度和 jerk：

```bash
./scripts/keyboard_control.sh --execute --joint-accel 0.3 --joint-jerk 1
```

速度限制的是关节命令，不是末端线速度。轨迹在关节空间插值，末端不严格走直线。
在模型中，从默认准备姿态以 2 mm 步长沿六个方向连续点动，参考 TCP 的横向偏差小于 0.5 mm；这只是模型结果。

松键、空格、失焦和跟踪保护会直接冻结当前命令位置，不再为了平滑减速而继续向原目标移动，
因此中断时速度和加速度不连续。

## 保持与承重

位置控制在重力作用下会留有一定的静差，这部分静差提供了承重力矩。为了不让机械臂每次点动后下沉一点，程序：

- 松键、空格和失焦时，把目标冻结在已经发送的关节命令上，不用实测角度重置参考；
- IK 从连续的命令参考开始求增量，实测反馈只用于限位、故障和跟踪检查；
- 参考与反馈的偏差超过 0.06 rad 时暂停生成新的点动目标，等反馈跟上。

状态栏的 `HOLD` 表示参考轨迹已经完成或被冻结，不表示实测误差为零。

## 保护与停止

控制进程持续检查：

- 关节目标和整条轨迹都不超出 URDF 限位；实测反馈允许超出限位 0.03 rad，以容忍编码器的微小偏差；
- 反馈在 200 ms 内更新，没有电机故障，各关节处于 FOC 状态；
- 每个点动目标与实测位置相差不超过 0.12 rad；命令领先反馈超过 0.08 rad 时暂停推进；
- 跟踪误差不超过阈值（`tuned` 0.1 rad，`legacy` 0.2 rad）；
- 键盘窗口的心跳间隔不超过 500 ms。

单个点动目标 5 s 内未完成、P 或 H 在 60 s 内未完成时，停在当前参考位置保持。

`tuned` 配置下，心跳丢失、跟踪超限、非法目标等故障会让机械臂在实测位置阻尼保持，不释放力矩；
按 Enter 在当前位置恢复位置保持。反馈中断、电机报错、退出 FOC、Esc 和程序退出会释放力矩。
`legacy` 配置下所有故障都释放力矩。

启动时，控制进程先以零力矩 FOC 请求反馈，再在当前反馈位置使能保持。这一步电机处于零力矩状态，
机械臂要有支撑。`tuned` 配置下，若有关节超出限位不到 0.2 rad（例如释放力矩后 J6 落到限位外），
使能后先把它平滑移回限位内。

程序不清除电机故障、不写零偏，也不做碰撞检查。软件停止不是硬件急停。
运行前关闭其他占用该串口的程序；控制进程会以独占方式打开串口，但无法赶走已经打开串口的进程。

## 日志

每次启动都会写一份 JSONL 诊断日志到 `build/keyboard/logs/keyboard-<时间戳>.jsonl`，终端会打印路径。
日志包含按键、命令、关节反馈和参考值。`--log /path/to/trace.jsonl` 可指定路径（追加写入）。

## 实现

`keyboard_control.py`（Pygame 窗口）→ 独立的 IK 进程（使用 `arm_control.ArmIK`）→
`r1_keyboard_worker`（C++ 控制进程，100 Hz，源码 `keyboard_native/worker.cpp`）。

- 按键用 Pygame 的按下、松开和窗口焦点事件，并定期与当前按键状态核对，防止漏掉松键事件。
- IK 在单独进程中运行，求解慢时不会阻塞窗口和心跳。松键或失焦时，尚未返回的 IK 结果作废。
- 轨迹平滑使用 [Ruckig v0.15.3](https://github.com/pantor/ruckig/tree/v0.15.3) 的 state-to-state C++ 实现，
  源码和许可证在 `keyboard_native/third_party/ruckig/`，构建和运行都不需要联网。
  每次规划还检查整条轨迹的位置极值，确保在线换目标时不越过 URDF 限位。
- 控制进程直接使用 SDK 的 `ArmMotorBus`、`config/joint_calib_right.txt` 和串口驱动源码。
- IK 的来源和坐标约定见 [README_ik.md](README_ik.md)。

## 安装与测试

Python 选择顺序与 `arm_control.sh` 相同：`R1_IK_PYTHON` → 仓库内 `.venv-ik` → 系统 `python3`。

```bash
python -m pip install -r scripts/requirements-keyboard.txt

# 单独构建到 build/keyboard/，不覆盖官方 SDK 的可执行文件和动态库
./scripts/build_keyboard.sh

# 原生测试：速度、加速度、jerk 限制，在线换点，限位和保持
ctest --test-dir build/keyboard --output-on-failure

# Python 测试，只使用模拟驱动
.venv-ik/bin/python -m pytest -q tests/test_keyboard_control.py tests/test_arm_control.py
```
